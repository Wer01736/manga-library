# WNACG 合輯章節模式：AI 實作交接文件

日期：2026-10-02。本文是實作規格與驗收依據。網站版第一階段已完成合輯目錄解析與逐話下載流程；Edge 擴充模式仍留待網站版驗證後再做。

## 目標與範圍

只處理 `漫畫網頁版_MVP` 的本機 ZIP／CBZ 下載與閱讀流程。**使用者只會提供一個 WNACG 目錄網址**，例如 `https://www.wnacg.com/photos-index-aid-390766.html`；使用者不負責提供話數、章節名稱或子連結。程式須自行讀取該頁，判斷是單本還是合輯，動態找出所有章節及各章圖片。單本沿用現有圖片下載；合輯先顯示實際總話數，再按章節順序各自下載成獨立 ZIP／CBZ。書庫中可逐話閱讀，且這些檔案應能以同一合輯名稱集中查看。不得修改舊版測試工具或「小說漫畫閱讀」專案。

## 判斷與下載流程

1. 僅接受既有白名單中的 WNACG 主機及預期的漫畫路徑。從使用者提供的**一個目錄網址**取得 HTML；失敗時回報連線錯誤，不能因抓不到章節就誤判為單本。若網站內容由 JavaScript 補上，應讀取完成後的 DOM 或其實際資料來源；這部分須以可連線的網站實測，不能猜 API。
2. 檢查頁面是否有章節目錄 `#sr_pub[data-aid]`。若有，合輯 ID 取 `data-aid`，從 `.sr_compact a[data-chid][href]` 動態擷取所有可見章節。**不要預設四個，也不要要求使用者貼子連結。** `data-order="asc"` 時沿用 DOM 順序；`desc` 時轉回第 1 話起的順序，並以畫面上的章節標示核對。每個連結須是白名單主機、`href` 的 `sid` 等於容器 `data-aid`、`href` 的 `aid` 等於 `data-chid`，且沒有重複章節。
3. 檢查目錄是否分頁或按需載入。畫面中的「1」只能證明此範例看到第 1 頁，不能證明所有合輯都只有一頁。若有下一頁或載入更多，沿站點實際提供的連結／資料請求逐頁讀取，合併去重後才決定總話數。若畫面／資料提供「共 N 話」，用 N 核對已收集的章節數；若沒有總數，只有在確認沒有下一頁或更多資料後，才用完整清單長度作為總話數。無法確認完整性時停止，不開始部分下載。
4. 若成功讀到完整頁面且沒有章節目錄，再檢查它是否具備單本漫畫的頁數和原圖清單；有才走原本單本流程。若只是缺少必要資料或網站改版，顯示解析錯誤，不把未知頁面當單本。若日後也接受某話網址，才從該話頁面的 `sid` 回找合輯目錄；這是加分路徑，不能成為主要輸入要求。
5. 在既有下載視窗列出合輯名稱、**動態取得的總話數**、每一話名稱、順序及頁數。依第 1 話至最後一話列入工作；每話各有壓縮檔、進度、失敗與重試紀錄。合輯各自分組顯示，進度直接放在對應章節列；完成後清除下載工作紀錄，章節仍保留「已在書庫」與閱讀入口。
6. 對完整目錄中的每個子連結，逐一進入該話頁面，再取得該話頁數及原圖清單，依現有流程驗證圖片、建立壓縮檔。辨識圖片資料時要確認網站是否要求 `photos-item` 或其他閱讀資料網址保留 `sid`；不能假定刪除 `sid` 後仍能正確讀取。已存在的話數跳過或暫停，不能覆蓋；後續新增話數時重新讀目錄，只補缺少的話數。
7. 網頁版的批次下載、`comic_bridge.py` 的預覽／去重，以及 Edge 擴充功能的一鍵下載都應使用同一套合輯判斷。若本機程式無法直接取得網站 HTML，Edge 助手可依使用者提供的目錄網址開啟來源頁並讀取其章節 DOM，再送交本機下載佇列；仍不應要求使用者自行提供話數或所有子連結。失敗時明示原因，不把合輯當單本誤下載。

## Edge 擴充模式第二階段（尚未實作）

若網站版日後遇到使用者環境的代理、TLS、Cookie 或網站防護問題，再把同一份章節 manifest 接到現有 Edge 助手的「瀏覽器解析」通道。專案對 18comic 和 nhentai 已有這種做法：助手在背景分頁開啟來源頁、等候頁面載入、執行頁面內的資料擷取，再把結果送回 `127.0.0.1:8766`。本階段不先修改擴充功能。

具體資料流如下：

1. 使用者在漫畫書庫只貼一個目錄網址，例如 `/photos-index-aid-390982.html`。
2. 書庫把網址交給 Edge 助手；助手驗證它是 WNACG 白名單主機及合法目錄路徑，然後建立非作用中的背景分頁。擴充功能的 `manifest.json` 需加入 WNACG 網域權限；目前雖然彈出視窗接受 WNACG 網址，背景解析器與網域權限尚未支援 WNACG。
3. 助手等候 `document.readyState` 完成，並額外等候 `#sr_pub` 或單本資訊區出現。只等待頁面載入事件不夠，因為章節區可能稍後才由 JavaScript 補上。逾時、驗證頁或空白目錄要明確報錯。
4. 若找到 `#sr_pub[data-aid]`，即判為合輯。擷取合輯 ID、作品標題、封面、作者、分類、標籤等可用資料，並從 `a[data-chid][href]` 收集章節名稱、章節 ID 和網址。每筆都核對 `data-chid == href 中的 aid`、`data-aid == href 中的 sid`。
5. 從章節區附近文字取得「共 N 話」作為預期總數。若目前唯一章節數等於 N，目錄完成；若少於 N，助手必須操作該章節元件的分頁，而不是臆測網址：有正常 `href` 時依連結逐頁開啟；只有按鈕／JavaScript 切頁時，在背景分頁觸發實際下一頁控制，使用 `MutationObserver` 等候 `.sr_compact` 內容改變，再繼續收集。每次以 `(sid, aid)` 去重，直到收集 N 話且沒有下一頁。遇到頁碼循環、沒有下一頁但數量不足、或超過合理安全上限時停止並報告「章節目錄不完整」。
6. 依章節元件給出的順序排列；`data-order="asc"` 保留順序，`desc` 則反轉回第 1 話到最後一話。章節文字中若能解析「第 N 話」，用它交叉核對順序；解析不到時保留網站順序，不按 `aid` 大小猜測。
7. 對每個章節，助手依序或以很低的並行數開啟其閱讀頁。從該頁讀取章節標題、頁數，並在同一瀏覽器來源中請求對應的 `photos-item-aid-章節ID-sid-合輯ID.html`；解析其中 `page_url` 原圖清單。原圖數必須與該話頁數相符，否則該話不進入下載。
8. 助手把每話整理為獨立 manifest：`source_site=wnacg`、`series_id`、`chapter_id`、`chapter_number`、合輯名稱、章節名稱、頁數、來源網址、圖片清單、分類與標籤。下載去重使用 `wnacg:chapter_id`，合輯歸組使用 `series_id`；不能用合輯 ID 當作每話的下載身分，否則第二話起會被誤判為重複。
9. `comic_bridge.py` 接收一個合輯 manifest 和多個章節 manifest；預覽畫面顯示實際總話數及每話狀態。確認完整後，沿用現有下載工作模型，為每話建立獨立工作與 ZIP／CBZ。若本機直接抓圖片遭遇 403、TLS 或 Cookie 問題，仿照現有 nhentai 流程，由 Edge 助手讀取圖片位元並逐頁傳給本機橋接服務。
10. 日後再次貼同一合輯網址時，重新讀完整目錄，以 `chapter_id` 比對既有實體 ZIP：已有的標示略過，新出現的章節加入下載。這樣合輯從 4 話增加到 6 話時，只補第 5、6 話。

## 網站版第一階段已完成項目

目前 `漫畫網頁版_MVP/app.py` 和 `static/enhancements.js` 已先實作網站版，不修改 Edge 擴充功能：

- `normalize_wnacg_album_url` 接受合輯首頁、分頁網址和帶 `sid` 的章節網址；不會把章節的 `sid` 丟掉。
- `WnacgSeriesParser` 從 `#sr_pub[data-aid]` 與同頁 `.sr_compact a[data-chid]` 讀取章節。解析不依賴 `#sr_pub` 必須包住 `.sr_compact`，因為目前實際 HTML 是兄弟節點。
- 由「共 N 話」核對實際章節數；若有目錄分頁會繼續讀取並去重，數量不一致時停止，不開始部分下載。章節順序使用網站 `data-order`，不以 `aid` 大小猜順序。
- 批次預覽收到一個合輯網址後會展開成實際章節清單；每章有自己的章節網址、頁數、檔名和下載狀態。預覽完成後保留完整清單，由使用者選擇「下載此話」或「下載全部可下載章節」，不再檢查後立即下載並移除清單。
- 每話保留章節頁實際作品名稱作為 ZIP 檔名；合輯 ID、章節 ID、章節順序、總話數及合輯名稱另存為書庫欄位，避免檔名規則與實際下載名稱不一致。
- 每章下載時重新讀取該章 `photos-item-aid-<aid>-sid-<sid>.html` 的原圖清單，沿用既有頁數與圖片驗證；不會把合輯首頁誤當成一個單本 ZIP。
- 已有 ZIP 會以 `chapter_id` 或實際路徑重新連回合輯，預覽中標示「已在書庫」並提供閱讀入口，不會建立失敗下載工作。

網站版不需要使用者提供話數或複製子網址。使用者只貼目錄首頁，預覽流程會自行展開所有章節。書庫作品詳情與獨立閱讀器都會顯示同一合輯的可捲動章節目錄；閱讀器切話從第一頁開始，不保存各話頁碼。

### 單本分流

成功取得完整 DOM 後，若沒有 `#sr_pub`，才檢查一般單本所需的作品名稱、頁數與 `photos-item` 原圖資料。三項成立才判定為單本。若頁面資料缺失、被導向驗證頁或網站結構不明，結果是「無法解析」，不可自動降級成單本。

## 閱讀模式的合輯目錄（網站版已實作）

這部分是使用者指定的網站版閱讀介面需求，與下載解析分開驗收。配色、按鈕風格、圓角、陰影和字體優先沿用目前漫畫網頁版的既有樣式，不另起一套顏色。

### 目錄頁

- 合輯進入書庫或預覽時，要呈現由網站實際讀到的章節總數與章節順序。
- 章節名稱、話數和日期（來源有提供時）以清單／框格呈現，長清單可垂直捲動。
- 點選某一話後，直接開啟該話閱讀內容；不可要求使用者自己複製子網址。
- 章節數量是動態資料，不能寫死為四話，也不能只顯示目前貼入的那一話。

### 閱讀模式底部目錄

- 閱讀畫面保留現有底部工具列，新增／啟用「目錄」入口；圖一顯示的目錄面板是參考樣式。
- 點擊「目錄」後，在閱讀畫面下方或工具列上方展開章節面板，顯示合輯名稱、目前總話數和章節清單。
- 清單可下拉捲動；每一列可點選，點選後跳到對應話的第一頁或該話閱讀入口。
- 目前話數要有清楚的選取／高亮狀態，使用現有的深色背景、灰階層次和強調色，不另加新的品牌色。
- 面板要能關閉，關閉後恢復原本閱讀區域；手機寬度下不可遮住必要的翻頁／關閉控制。

### 閱讀進度規則

- **不記錄每一話的頁碼進度。** 不建立或更新「第 N 話讀到第 M 頁」的跨次回復資料。
- 使用者在目錄中主動點選哪一話，只負責當次跳轉；重新開啟時可回到合輯入口或使用者明確選擇的話，但不顯示上一話的頁碼。
- 不得沿用目前可能依漫畫檔案保存的逐頁閱讀標記來冒充合輯進度；合輯目錄高亮只表示當前畫面所在話。

### 驗收畫面

- 圖一：閱讀工具列點「目錄」後，可看到合輯名稱、總話數、可捲動的章節列和目前話數。
- 圖二：初次進入合輯時，下方有可展開的章節框格／選單；每一列可直接點入該話，樣式沿用現有顏色。
- 長達 7 話、10 話或更多時仍可捲動；不因清單變長破壞閱讀區。
- 切換到另一話後，不會替各話寫入頁碼進度；關閉再開也不會顯示虛假的「上次讀到第幾頁」。

### 需要修改的現有元件（實作時）

- `edge-extension/manifest.json`：加入 WNACG 網域權限並提高版本。
- `edge-extension/service-worker.js`：新增 WNACG 網址辨識、目錄／分頁／章節／圖片解析，以及必要時的瀏覽器圖片傳送。
- `static/enhancements.js` 與 `edge-extension/library-bridge.js`：把 WNACG 送入瀏覽器解析流程，接收「一個網址展開多話」的結果。
- `comic_bridge.py`：允許 `source_site=wnacg`，儲存合輯與每話 manifest，使用章節 ID 去重，並把各話送入原有下載佇列。
- `app.py`：保留原有單本後端解析作為可用時的路徑；網址解析需理解可選 `sid`，但不可把刪除 `sid` 當成合輯支援。

## 驗收條件

- **只貼上**合輯首頁 `https://www.wnacg.com/photos-index-aid-390766.html`，預覽能自行找出本例的四話及順序，不需要使用者再貼四個子網址。
- 用不同測試目錄驗證 1、2、10 話及跨多頁的合輯；顯示的話數必須由實際完整清單決定，不可固定為四話。總數與已抓清單不符時，不得開始部分下載。
- 單本網址仍走原有單本流程；不會因頁面其他推薦連結而被誤判為合輯。
- 本例的四話分別下載成可閱讀的 ZIP／CBZ；其他合輯則依其實際話數下載。已有檔案不被改寫；單話失敗能清楚定位並重試。
- 用測試 HTML 驗證不同話數、目錄分頁、倒序顯示、重複 `data-chid`、錯誤 `sid`、總數不符及不完整目錄；用測試圖片與壓縮檔驗證下載，不以真實收藏做第一次測試。依 `AGENTS.md` 執行 Python、JavaScript 語法檢查及現有測試。
